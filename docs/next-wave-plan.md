## Execution order and parallel ownership

Start steps 1–2 together: access/source discovery can proceed while cloud settings are supplied. After contracts settle, SIRUP/storage work (3–4), SSH preparation (6), and tender retrieval (9) can run in parallel on disjoint adapters and fixtures. Step 5 needs the authorized cloud settings and storage contract; steps 7–8 need the cloud baseline. Public real-case release requires completed review/publication controls, grounded findings and dossier checks (10–12).

Suggested agent ownership: data ingestion and canonical records; grounded analysis/security; frontend/API integration and browser acceptance. The coordinating agent owns shared contracts, schema migrations and release validation. One agent owns each file at a time. Agree JSON envelopes, status vocabulary, pagination and amount precision before changing callers. Keep existing offline tests and fixture mode operational throughout; live probes are opt-in and excluded from default tests.

No fixed calendar estimate is promised before sample coverage and cloud access are known. Measure each successful probe and revise the next step's estimate from that evidence.

## Release checklist

- [ ] Approved project/billing/spend/region settings recorded; actual usage measured against the remaining allowance. Alerts are supplemented by application/query/concurrency caps.
- [ ] At least one authentic planning record and applicable price source can be independently checked; synthetic records remain separate and labeled.
- [ ] Verified tender link and sufficient evaluation data exist for any lifecycle claim; otherwise declare the missing gate and obtain a reduced-scope decision.
- [ ] Decimal/integer-IDR contract, unknown fields, provenance, comparability and effective-dated rule tests pass.
- [ ] Model schema, grounding, bounded execution, Model Armor enforcement and invalid-input negative cases pass in the actual project.
- [ ] Private source objects, role checks, exact-version approval, public redaction and withdrawal tests pass.
- [ ] Public filtering → detail → benchmark/counterevidence → graph/table → both draft downloads succeeds on the deployed service, including keyboard and narrow viewport checks.
- [ ] Source outage, model failure, retried job and stale case versions degrade safely and visibly.
- [ ] No credentials/private source data in Git, container layers, browser assets, logs or traces. Source redistribution is permitted for every committed specimen.
- [ ] Deployed revision, image digest, tested model/policy versions, query/job references and safe trace evidence recorded. Rollback tested against the prior revision and compatible data schema.
- [ ] Owner-facing delivery notes distinguish live integrations, unavailable coverage, measured costs and remaining limitations. No competition submission or outbound dossier filing is implied.
