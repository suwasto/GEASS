# GEASS Google Cloud feasibility

Verified against first-party documentation on **2026-10-14 (Asia/Jakarta)**. This is documentation research, not a deployed proof. PRD references to Vertex AI Search/Vertex AI remain understandable, but some current documentation redirects to Agent Search/Gemini Enterprise Agent Platform. Product naming alone does not prove that the project's API or SDK configuration works.

## Verified capabilities and corrections

| PRD assumption | Verified finding | Architectural consequence (recommendation) |
| --- | --- | --- |
| BigQuery Graph is the graph backend | BigQuery Graph is real: graphs map existing tables/views into nodes/edges and support GQL. GQL requires an Enterprise or Enterprise Plus reservation; on-demand supports SQL `GRAPH_EXPAND`. The overview does not display a Preview banner. [BigQuery Graph overview](https://docs.cloud.google.com/bigquery/docs/graph-overview), [create/query](https://docs.cloud.google.com/bigquery/docs/graph-create) | Keep BigQuery as the analytical source. Use ordinary SQL co-bidding/address joins for the initial slice; enable GQL only after a project/edition/budget probe. Do not claim GQL has been exercised when only SQL ran. |
| A graph automatically serves the interactive drawer | Google's comparison puts BigQuery Graph in batch analytics (seconds to hours) and Spanner Graph in operational low-latency workloads (milliseconds to seconds). [comparison](https://docs.cloud.google.com/bigquery/docs/graph-compare) | Precompute small graph projections per case and serve those. Do not add Spanner solely to render a graph; revisit only if measured interactive workload requires it. |
| ADK Python can deploy on Cloud Run | Official guides support Python ADK on Cloud Run. ADK CLI deployment and a custom FastAPI container are both documented; development UI inclusion is optional. [ADK deployment](https://github.com/google/adk-docs/blob/main/docs/deploy/cloud-run.md), [Cloud Run quickstart](https://docs.cloud.google.com/run/docs/quickstarts/build-and-deploy/deploy-python-adk-service) | A custom application can expose read-only public case APIs while protecting agent execution. Deploying ADK does not by itself provide safe public endpoints or resumable batch work. |
| ADK supplies asynchronous checkpointing automatically | ADK session services record session history/state, but `InMemorySessionService` loses everything on restart. Persistent services are distinct choices. [session services](https://adk.dev/sessions/session/) | Persist run/stage outcomes outside container memory. Initially re-run a bounded case from its last durable stage; require an explicit retry/idempotency contract. Avoid promising arbitrary task resumption based solely on ADK sessions. |
| Vertex AI Search means live web prices | Grounding with Agent Search uses an explicitly configured document/website datastore; it supports document import from Cloud Storage and up to ten grounding data sources. [datastore grounding](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-vertex-ai-search) | Index versioned SSH/SBU evidence separately. Website indexing does not guarantee e-Katalog/retail coverage, freshness, or procurement-equivalent prices. |
| The same search retrieves public web knowledge | Grounding with Google Search uses public web data; publishers can exclude pages using Google-Extended. Returned grounding metadata can be absent. Search Suggestions and grounding support have display requirements. [Google Search grounding](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-google-search) | Treat web prices as advisory candidates. Retain URLs, retrieval time, exact unit/spec/tax/logistics assumptions; abstain if no comparable price is evidenced. Provide required search UI when showing Search-grounded responses. |
| Model Armor neutralizes every poisoned document | Screening has explicit limits and the caller/integration must enforce blocking verdicts. [Model Armor overview](https://docs.cloud.google.com/model-armor/overview), [limits](https://docs.cloud.google.com/model-armor/quotas) | Treat it as one detector, with a fail-closed application gate, restricted tools, schema validation, and human review. Never label a skipped/failed scan as safe. |
| Gemini 2.5 Pro/Flash are durable implementation choices | Both official model pages announce retirement on **2026-10-20**, six days after this research. Both currently document structured output and function calling. [2.5 Pro](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/2-5-pro), [2.5 Flash](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/2-5-flash) | Block selecting 2.5 as the long-lived baseline. Choose and pin a supported model only after project/region tests and evaluation; record its ID in each result. |

## Security and integration details that must reach tickets

Model Armor checks one turn at a time, does not inspect encoded content, and does not screen images embedded in files. Files over 4 MB are skipped. Indonesian is absent from the overview's tested prompt-injection language list, so local efficacy is unknown. Inspect-only mode does not block. These limits make a poisoned-document demo an example, not proof of complete protection. [overview](https://docs.cloud.google.com/model-armor/overview)

The quota page specifies a 65,536-token screening extent for injection/jailbreak filters and describes `EXECUTION_SKIPPED` outcomes; inspect individual filter status and failure fields, not merely HTTP success. Quarantine unsupported, incomplete, failed, or skipped scans; OCR scanned PDFs before text screening, preserving page provenance. This quarantine/OCR policy is a GEASS recommendation. [quotas and limits](https://docs.cloud.google.com/model-armor/quotas)

Search-grounding documentation currently warns against mixing search and non-search tools in one `generateContent` request, while model migration documentation advertises expanded combinations in newer models. Do not infer compatibility for a chosen model/SDK from generic guidance: use separate retrieval/function stages initially and test the exact combination before enabling it. [Search considerations](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-google-search), [migration guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/migrate)

Datastore grounding can return no grounding metadata when relevance/information is insufficient; Gemini 2.5 and later do not provide its listed grounding confidence scores. A citation is support for a claim, not a calibrated anomaly probability. [response metadata](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-vertex-ai-search)

The migration guide lists GA Flash successors and GA Gemini 4 Argon alongside preview Pro choices, recommends prompt evaluation, and documents changed parameters/tool-response requirements. A currently documented successor is not proven available to this project. Prefer one supported GA model for the first slice; add a second reasoning model only if evaluation justifies it. [model migration](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/migrate)

## Recommended gates before implementation expansion

1. **Cloud access/model gate:** verify billing, enabled APIs, least-privilege service identity, selected region, quota, current model ID/retirement date, structured-output parsing, and one supported grounded call. Capture evidence; do not create unrestricted public agent execution.
2. **Graph gate:** verify actual reservation edition and estimate/query-cap cost before GQL. Demonstrate a co-bidding and shared-address query with provenance; default to SQL plus precomputed graph JSON if GQL is unavailable or exceeds budget. The graph remains an evidence visualization, not proof of affiliation.
3. **Grounding gate:** retrieve a known regional/year-specific SSH row and exact page. Reject unknown unit, bundled `1 Paket`, incompatible spec, wrong fiscal year, or absent grounding support. Demonstrate that missing evidence produces insufficient-evidence status, not markup.
4. **Armor gate:** test benign and Indonesian/English adversarial text, OCR text, encoded content, oversized input, service timeout, and skipped scans. Record scan status and blocked stage. Fail closed for new analysis/publication when screening is incomplete; previously reviewed read-only cases may remain visible.
5. **Durability gate:** interrupt after a stage commit, restart, retry, and verify that case outputs are neither duplicated nor marked completed early. ADK conversation persistence and GEASS analysis completion are separate responsibilities.
